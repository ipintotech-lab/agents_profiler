PPOC — sample-size stabilization experiment

    
This answers one question: how much synthetic trace data does the profiler actually need before its determinism calls stop changing? It is not looking for the sample size with the highest accuracy — it is looking for the smallest sample size beyond which feeding it more data stops meaningfully improving the result. Below that point, trust the numbers less; above it, more data is just cost with no added benefit.

    
How it gets there, phase by phase: (1) pick the best determinism thresholds by voting across several independent "calibration" datasets; (2) freeze those thresholds and re-run the profiler at increasing sample sizes on a completely separate set of "validation" datasets, watching where accuracy/recall/coverage level off; (3) check that the profiler's worst-offender recommendation is stable at that sample size, not a coin flip between seeds; (4) sanity-check the resulting B-POP capacity recommendation against the same workload; (5) model what the measured determinism rate would be worth in avoided LLM calls. Calibration and validation always use non-overlapping seeds, so the thresholds are never graded on the same data they were chosen from.

    


    
Phase 1 — calibration

    
Grid-searches the three determinism thresholds (min_repeated_inputs, min_repeat_coverage, min_repeated_observations) across every calibration seed together, and compares the best-scoring combination against the thresholds this app currently ships with. "Selected" is what Phase 2 onward actually uses — not automatically applied to the live defaults.
